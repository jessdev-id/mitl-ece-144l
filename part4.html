Mission 04 · Culminating Activity

Campus Interbuilding Routing Commissioning Challenge

Three campus buildings—Engineering, Administration and Research—must communicate across a routed backbone. You are the assigned network engineer. Commission dual-stack links, document routing-table decisions, implement static routes, migrate IPv4 routing to single-area OSPFv2 and recover from a deliberate transit-link outage. Deliver two independently working Packet Tracer snapshots: static routing and OSPFv2.

Estimated duration
180–240 minutes
Work mode
Individual · Hands-on
Deliverables
2 .pkt files + evidence report
01 · Mission Brief

Scope and success criteria

Learning targets

Chapter 14: interpret route codes, next hops, administrative distance and longest-prefix matching. Chapter 15: configure IPv4/IPv6 static and default routes. Chapter 16: configure and verify single-area OSPFv2.

Successful outcome

All LANs communicate by IPv4 and IPv6 using static routes; a separate snapshot routes IPv4 through OSPFv2 while IPv6 retains static routing. Students explain route entries, observe adjacency changes, restore service and save verified configurations.

Required equipment

Cisco Packet Tracer; 3 Cisco 2911 routers (R1–R3); 3 Catalyst 2960 switches (SW1–SW3); 3 PCs (PC-A–PC-C); suitable Ethernet cables. All router configurations must use Cisco IOS CLI. The PC Desktop IP Configuration utility may be used for end-device addressing.

04 · IOS Command Reference

CLI configuration and verification guide

Reference commands show prompt modes. Adapt interface addressing for R2/R3 using the table; do not paste router prompts into the Cisco CLI.

R1 — IPv4/IPv6 interfaces and static routes

Router> enable
Router# configure terminal
Router(config)# hostname R1
R1(config)# ipv6 unicast-routing
R1(config)# interface gigabitethernet0/0
R1(config-if)# description ENGINEERING_LAN
R1(config-if)# ip address 192.168.10.1 255.255.255.0
R1(config-if)# ipv6 address 2001:DB8:144:10::1/64
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface gigabitethernet0/1
R1(config-if)# description TO_R2_GI0/1
R1(config-if)# ip address 10.0.12.1 255.255.255.252
R1(config-if)# ipv6 address 2001:DB8:144:12::1/64
R1(config-if)# no shutdown
R1(config-if)# exit

OSPFv2 — example for R1 (repeat with router-specific networks)

R1> enable
R1# configure terminal
R1(config)# no ip route 0.0.0.0 0.0.0.0 10.0.12.2
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# passive-interface gigabitethernet0/0
R1(config-router)# end
R1# show ip ospf neighbor
R1# show ip route ospf
R1# copy running-config startup-config

For R2: advertise 192.168.20.0/24, 10.0.12.0/30 and 10.0.23.0/30 with matching wildcard masks; router-id 2.2.2.2. For R3: advertise 192.168.30.0/24 and 10.0.23.0/30; router-id 3.3.3.3. On all routers, make Gi0/0 passive. Remove all remaining IPv4 static routes before verifying OSPF learning. IPv6 static routes remain in place.

05 · Fault Injection

Controlled troubleshooting challenge

Fault A — Missing IPv4 static route

In the static-routing snapshot, remove R2's route to 192.168.30.0/24. Test PC-B → PC-C and inspect show ip route. Restore the route and retest. Explain why directly connected subnets continue to work.

Fault B — OSPF adjacency loss

In the OSPF snapshot, shut down R2 Gi0/2. Record neighbor changes, missing routes and connectivity failure; restore the interface, wait for adjacency and route recovery, and repeat pings.

Restore injected faults before final submission. Diagnose physical/interface status first, then addressing, neighbors and route entries.
